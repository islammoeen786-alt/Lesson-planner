## 1. Overview

### 1.1 Product Summary
Smart Lesson Planner is a mobile-first app that helps K-12 teachers turn a short description of what they need to teach into a complete, editable, classroom-ready lesson plan — generated by AI in seconds instead of written by hand over an hour.

### 1.2 Problem Statement
Lesson planning is one of the most time-consuming, repetitive parts of teaching. Most teachers either write plans from scratch every week or reuse generic templates that don't really fit their class, their grade level, or the time they actually have. Existing lesson-planning software tends to be built for large school districts — expensive, heavy, and overkill for an individual teacher who just wants a good plan, fast.

### 1.3 Solution
Smart Lesson Planner gives an individual teacher a lightweight tool that:
- Generates a full, structured lesson plan from a short form, using Gemini
- Lets them edit, save, and organize plans in one personal library
- Exports a clean, printable PDF
- Runs on a deliberately lean stack (SQLite + shared hosting) so it costs next to nothing to operate at MVP scale — no cloud infrastructure bill to justify before there are real users

## 2. Goals & Success Metrics

### 2.1 Business Goals
- Ship a working MVP quickly on infrastructure that's nearly free to run
- Validate real demand for AI-assisted lesson planning before investing in a heavier stack
- Keep AI cost per user predictable and capped from day one

### 2.2 User Goals
- Cut lesson-planning time from ~45–60 minutes to under 5 minutes per lesson
- Get plans that are actually usable in class, not generic filler
- Build a searchable personal library of everything they've planned

## 3. Target Users & Personas

### 3.1 Primary — "The Classroom Teacher"
Teaches primary or secondary school, 15–30 students. Comfortable with a smartphone, not necessarily with complex software. Plans lessons weekly or nightly, often on the move. Wants speed and reliability over configurability.

### 3.2 Secondary — "The Operator" (you / admin)
Runs the product, manages the Gemini API key and the cost that comes with it. Needs visibility into signups, usage, and spend without a dedicated ops team. Uses the admin panel, never the mobile app.

> This PRD designs the admin panel as a single-operator console (you managing all teacher accounts), not a per-school, multi-tenant admin hierarchy. If you actually need school-level admins later, that changes the schema in Section 10 — flag it now if so.

## 6. Tech Stack

| Layer | Choice | Notes |
|---|---|---|
| Mobile frontend | Flutter (Android + iOS) | One codebase for both platforms |
| Backend | Node.js + Express | Plain JavaScript, no TypeScript build step — matches "no build setup" on cPanel |
| Database | SQLite | File-based, no separate DB server — a natural fit for shared hosting |

### 6.1 Suggested Libraries
- **Backend:** `express`, `better-sqlite3` (or `sqlite3` as a fallback — see Section 15.10), `jsonwebtoken`, `bcrypt`, `express-validator`, `express-rate-limit`, `nodemailer`, `cors`, `dotenv`, `pdfkit` (pure-JS PDF generation — avoids needing a headless browser like Puppeteer, which is heavy and often unreliable on shared hosting)
- **Flutter:** `dio` or `http` for networking, `flutter_secure_storage` for token storage, `provider` or `riverpod` for state management, `share_plus`/`url_launcher` for sharing the exported PDF

## 8. Functional Requirements

### 8.1 Authentication & User Management
- **FR-1.1** Register with name, email, password (bcrypt-hashed, minimum 8 characters)
- **FR-1.2** Login returns a short-lived access token (JWT, ~15–30 min) plus a longer-lived refresh token (~30 days)
- **FR-1.3** Refresh endpoint rotates the refresh token and issues a new access token
- **FR-1.4** Forgot password sends a time-boxed reset link (1-hour expiry) to the registered email
- **FR-1.5** Logout revokes the current refresh token
- **FR-1.6** Profile screen: edit name, school name (optional), subjects taught, grade levels taught, language preference

### 8.2 AI-Powered Lesson Plan Generation
- **FR-2.1** Form inputs: subject, grade/class level, topic, duration, optional learning objectives, optional teaching style, optional extra instructions
- **FR-2.2** On submit, the backend builds a structured prompt and calls Gemini requesting JSON output (see Section 12)
- **FR-2.3** Generated plan includes: title, objectives, materials, warm-up/introduction, main teaching activity, practice/group work, assessment, homework, and closing summary — each with a time allocation
- **FR-2.4** Teacher can regenerate the whole plan, or just one section (e.g. only "main activity"), without redoing the rest
- **FR-2.5** Generated plan is editable inline before saving
- **FR-2.6** If generation fails (API overload, timeout, malformed response), retry automatically with backoff before surfacing an error (Section 12.4)

### 8.3 Lesson Plan Management
- **FR-3.1** Save, view, edit, duplicate, delete lesson plans
- **FR-3.2** List view with search (title/topic) and filters (subject, grade, date range)
- **FR-3.3** Mark a plan as draft or final
- **FR-3.4** Optional scheduled date per plan (a simple list/calendar view, not a full calendar app)

### 8.4 Templates
- **FR-4.1** A small set of built-in starter templates by subject, for teachers who want a starting point instead of a blank AI prompt
- **FR-4.2** Templates are read-only system content, managed from the admin panel

### 8.5 Export & Sharing
- **FR-5.1** Export a lesson plan to a print-formatted PDF
- **FR-5.2** Share the PDF via the device's native share sheet

### 8.6 Usage Quotas
- **FR-6.1** Each account gets a set number of AI generations per calendar month (configurable in admin settings, default 20)
- **FR-6.2** App shows remaining quota; blocks *generation* (never saving/editing) once quota is hit, with a clear message
- **FR-6.3** Manual (non-AI) lesson plan creation is never quota-limited

### 8.7 Admin Panel
- **FR-7.1** Login with the same JWT auth, `role = admin`
- **FR-7.2** Dashboard: total users, total lesson plans, generations this month, estimated Gemini spend this month
- **FR-7.3** User list: search, view detail, activate/deactivate an account
- **FR-7.4** Lesson plan moderation view: browse/flag inappropriate AI output
- **FR-7.5** Settings: Gemini API key, default quota, feature flags, announcement banner
- **FR-7.6** Template management: add/edit/remove starter templates

### 8.8 Notifications (Phase 2 — not in MVP)
Placeholder for future in-app reminders (e.g. "you haven't planned next week yet").

## 9. Non-Functional Requirements

| Category | Requirement |
|---|---|
| Performance | AI generation completes in < 15s for 95% of requests; non-AI API responses < 500ms |
| Security | Passwords hashed with bcrypt (cost ≥ 10); JWTs signed with a strong secret stored only in environment variables; all traffic over HTTPS |
| Reliability | Gemini calls wrapped in retry logic (exponential backoff, max 3 attempts) for rate-limit/overload errors |
| Scalability | SQLite in WAL mode comfortably handles a few hundred concurrent users on this read-heavy, write-light workload; plan a migration path to MySQL/Postgres if usage grows well past MVP scale |
| Data backup | Automated daily copy of the SQLite file to a separate backup location (cPanel cron job) |
| Localization | UI strings and AI prompts structured so Urdu (or another language) can be added later without a rewrite |
| Accessibility | Standard Flutter accessibility support (screen reader labels, scalable text) |
| Privacy | No individual student data is stored — plans reference a class/grade level, not named students |

## 12. AI Integration (Gemini API)

### 12.1 Model Choice
Gemini's API has moved fast — the 1.0/1.5 model families are fully retired, and 2.0 Flash/Flash-Lite were shut down on June 1, 2026, so anything still pinned to those needs to move to a current generation. As of mid-2026, the practical options for this app are:

| Model | Good for | Approx. cost (per 1M tokens, input/output) |
|---|---|---|
| **Gemini 2.5 Flash-Lite** | Cheapest option; fine for simple, well-structured generation | ~$0.10 / $0.40 |
| **Gemini 2.5 Flash** *(recommended default)* | Best balance of quality and cost for structured lesson content | ~$0.30 / $2.50 |
| **Gemini 2.5 Pro / 3.1 Pro** | Escalate here only if plan quality on Flash isn't good enough | ~$1.25–2 / $10–12 |

**Recommendation:** start with **Gemini 2.5 Flash** as the default generation model — it's stable (not experimental), inexpensive at this app's volume, and more than capable of structured, well-organized lesson content. Keep **Flash-Lite** as a config option if you need to stretch the free quota further at scale. Note that Google restricted its free API tier to Flash/Flash-Lite models only (Pro tiers became paid-only from April 2026), so budget for paid usage from day one rather than assuming a free allowance covers Pro-quality output. Treat the model name as a config value (in `admin_settings`), not a hardcoded string, so it can be swapped without a redeploy as Google's lineup keeps moving.

### 12.2 Prompt Design
Build the prompt server-side from the form fields (never let the client send a raw prompt). Roughly:

> "You are an experienced {gradeLevel} {subject} teacher. Create a detailed, classroom-ready lesson plan on the topic '{topic}' for a {durationMinutes}-minute class. {additionalInstructions}. Return only the lesson plan — no commentary, no markdown, just the structured content."

### 12.3 Structured Output
Use Gemini's JSON mode rather than parsing free-form text: set `generationConfig.responseMimeType` to `application/json` and pass a `responseSchema` describing the exact lesson-plan shape (see Section 20 for the full schema). This is a stable, well-documented feature on Gemini 2.5+ models and guarantees a parseable, predictable response instead of hoping the model formats things consistently.

### 12.4 Error Handling & Retry
- Wrap every Gemini call in retry logic: on a rate-limit or overload response, retry with exponential backoff (e.g. 1s → 2s → 4s), max 3 attempts
- If all retries fail, return a friendly in-app error ("Couldn't generate a plan right now — try again in a moment") rather than a raw error, and don't burn a quota credit on a failed attempt
- Log every attempt (success or failure) to `ai_generation_logs` for debugging and cost tracking

### 12.5 Cost & Quota Control
- Enforce the monthly quota (Section 8.6) *before* calling Gemini, not after — check `usage_quota`, reject if exhausted, only increment on a successful generation
- Log `tokens_used` per call where the API returns it, so the admin dashboard's "estimated spend this month" is grounded in real usage rather than a guess
- Re-verify current pricing at Google's official Gemini API pricing page before launch — rates above are a mid-2026 snapshot and Google adjusts them periodically

## 15. Deployment Plan (cPanel)

1. In cPanel, use **Setup Node.js App**, select an available Node LTS version, and set the application root and startup file (e.g. `server.js`)
2. Upload the backend code (excluding `node_modules`) via Git or File Manager/FTP
3. Install dependencies through cPanel's Node interface ("Run NPM Install") or by activating the app's virtualenv over SSH — no separate build step, since it's plain JavaScript
4. Set environment variables in the cPanel Node app config: `JWT_SECRET`, `JWT_REFRESH_SECRET`, `GEMINI_API_KEY`, `SMTP_*` credentials, `NODE_ENV=production`
5. Keep the SQLite database file outside the publicly served web root, with file permissions the Node process can read/write
6. Enable WAL mode on the SQLite connection at startup
7. Serve the admin panel's static files (`index.html`, CSS, JS) from the same Express app via `express.static`, or point a subdomain/subdirectory at those files
8. Point your domain/subdomain at the Node app through cPanel's app URL mapping, and enable free SSL (AutoSSL) for HTTPS
9. Set up a daily cron job (cPanel Cron Jobs) to copy the SQLite file to a backup location — ideally off-server (emailed, or pushed to cloud storage)
10. **Test native module installation early.** `better-sqlite3` (and, to a lesser extent, `sqlite3`) compiles native code, and some shared hosts restrict that. Install it on the actual cPanel host as one of the very first steps — before building anything on top of it — so you find out immediately if you need to fall back to a pure-JS/WASM option like `sql.js`
11. Set up outbound email for password-reset links: either the cPanel mail account's SMTP credentials via `nodemailer`, or a transactional email service (SendGrid, Mailgun, Brevo) for better deliverability, since shared-hosting IPs are sometimes flagged as spam sources

## 16. Security Considerations

- Bcrypt password hashing, cost factor ≥ 10
- JWT secrets live only in environment variables, rotated periodically
- Refresh tokens stored as hashes, revocable, rotated on every use
- Rate limiting on `/api/auth/*` and `/api/ai/*` (`express-rate-limit`) to block brute-force attempts and cost abuse
- Input validation/sanitization on every endpoint (`express-validator`)
- HTTPS enforced everywhere; redirect HTTP → HTTPS
- CORS restricted to the admin panel's origin and any future web client — the Flutter app isn't subject to browser CORS
- Gemini API key stored server-side only, never shipped inside the Flutter app
- Parameterized SQL queries everywhere — never string-concatenated SQL

## 17. Monetization Strategy (Future — Not in MVP)

- MVP ships free, with a monthly AI-generation quota as the only cost control — no payment integration needed at launch
- A future paid tier could raise or remove the quota, and add extras like bulk export, more templates, or priority generation
- If the target market ends up being Pakistan specifically, mobile wallets like **JazzCash** and **Easypaisa** are worth adding alongside or instead of card processors, since they're the dominant payment rails for many local users there
- The schema already leaves room to add a `plan_tier` field to `users` later without a painful migration

## 19. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Native SQLite module fails to install on the shared host | Test on the real host on day one; fall back to `sql.js` (WASM) or `sqlite3` with prebuilt binaries if needed |
| Gemini API cost scales faster than expected | Hard per-user monthly quota; admin dashboard cost tracking; alert thresholds in settings |
| Shared-hosting Node process gets recycled or sleeps when idle | Confirm behavior with the host; add a lightweight uptime ping if needed |
| No OTP/2FA means a lighter account-security posture | Acceptable trade-off for an MVP; revisit optional 2FA later if it becomes a real concern |
| SQLite write contention as the user base grows | WAL mode covers MVP scale; monitor usage; have a MySQL/Postgres migration path ready if it's outgrown |
| AI-generated content has factual or pedagogical errors | Never auto-publish AI output as final — always route through the teacher's review/edit step before saving |

## 20. Appendix: Sample Prompt & JSON Response Shape

**Example `responseSchema` for `/api/ai/generate`:**
```json
{
  "type": "object",
  "properties": {
    "title": { "type": "string" },
    "subject": { "type": "string" },
    "gradeLevel": { "type": "string" },
    "durationMinutes": { "type": "integer" },
    "learningObjectives": { "type": "array", "items": { "type": "string" } },
    "materials": { "type": "array", "items": { "type": "string" } },
    "sections": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "name": { "type": "string" },
          "durationMinutes": { "type": "integer" },
          "description": { "type": "string" }
        },
        "required": ["name", "durationMinutes", "description"]
      }
    }
  },
  "required": ["title", "subject", "gradeLevel", "durationMinutes", "learningObjectives", "materials", "sections"]
}
```

**Example generation request (server → Gemini):**
```json
{
  "contents": [{
    "role": "user",
    "parts": [{
      "text": "You are an experienced Grade 5 Science teacher. Create a detailed, classroom-ready lesson plan on the topic 'Photosynthesis' for a 40-minute class. Focus on a hands-on activity if possible. Return only the lesson plan — no commentary."
    }]
  }],
  "generationConfig": {
    "responseMimeType": "application/json",
    "responseSchema": { "...": "as above" }
  }
}
```

The response lands as JSON matching that schema, which is stored directly in `lesson_plans.content` and rendered by the Flutter app section-by-section — no free-text parsing required.
